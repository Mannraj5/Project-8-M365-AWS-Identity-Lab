# Lifecycle test: joiner → mover → leaver (T3.4–T3.6)

Test person: **Nina Patel** (fictional), 2026-11-21, tenant on Entra ID Free.
Transcripts are copied from the PowerShell output; the tenant domain is replaced
with `<tenant>`. Times are local (AEDT, UTC+11) unless marked Z.

## T3.4 Joiner (Finance)

Added to `data/users.csv`, then:

```text
PS> ./scripts/graph/New-LabUsers.ps1 -Domain <tenant>
SKIP   olivia.owner@<tenant> (already exists)      ... 8 existing users skipped
CREATE nina.patel@<tenant> (Finance)
Done: 1 created, 8 already existed.

PS> ./scripts/graph/New-LabGroups.ps1 -Domain <tenant> -FreeTier
MEMBER nina.patel@<tenant> -> SG-All-Staff
MEMBER nina.patel@<tenant> -> SG-Dept-Finance
SKIP   licensing (Entra ID Free has no licences to assign)
```

Result: in SG-All-Staff and SG-Dept-Finance. MFA registration on first sign-in is
enforced by Security Defaults (proven in T1.4). No licence on Free (EX-004).

## T3.5 Mover (Finance → Advice)

```text
PS> Update-MgUser -UserId nina.patel@<tenant> -Department 'Advice' -JobTitle 'Client Services Officer'
PS> ./scripts/graph/New-LabGroups.ps1 -Domain <tenant> -FreeTier
MEMBER nina.patel@<tenant> -> SG-Dept-Advice
REMOVE nina.patel@<tenant> from SG-Dept-Finance (department or account no longer matches)
```

Result: old department access removed in the same run that granted the new one,
so there is no privilege creep. SG-All-Staff membership unchanged.

## T3.6 Leaver

Dry run first (`-WhatIf`), then the real run at 2026-11-21T02:46:54Z (13:46:54 local):

```text
PS> ./scripts/graph/Invoke-Leaver.ps1 -UserPrincipalName nina.patel@<tenant> -WhatIf
START  leaver for nina.patel (department: Advice)
What if: Performing the operation "Block sign-in" on target "nina.patel@<tenant>".
What if: Performing the operation "Revoke sign-in sessions" on target "nina.patel@<tenant>".
What if: Performing the operation "Remove nina.patel" on target "SG-All-Staff".
What if: Performing the operation "Remove nina.patel" on target "SG-Dept-Advice".
INFO   no direct licences
END    script finished in 0s

PS> ./scripts/graph/Invoke-Leaver.ps1 -UserPrincipalName nina.patel@<tenant>
START  leaver for nina.patel (department: Advice)
(confirmed with "Yes to All")
```

Access check straight after the run, in a new private browser window:

> *Your account has been locked. Contact your support person to unlock it, then try again.*

Evidence: `screenshots/T3.6-leaver-signin-refused.png`. The script's own log is in
`out/leaver-nina.patel-*.log` (git-ignored, kept locally).

Result: sign-in refused on the first attempt after the run, well inside the
15-minute target. On Free, the leaver script removes group memberships directly
(they are assigned groups), so no separate sync is needed.

## Lesson learned during the test

The first leaver attempt failed before doing anything: the script's `#Requires`
named a module (`Microsoft.Graph.DeviceManagement.Actions`) that does not exist
in Graph SDK v2. Mock tests strip `#Requires`, so they missed it. Fixed in
`a2f3b43`; CI now checks every `#Requires` module name against the PowerShell
Gallery.
