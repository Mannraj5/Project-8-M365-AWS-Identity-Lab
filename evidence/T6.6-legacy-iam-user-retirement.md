# T6.6 Retire a legacy IAM user

Date: 2026-11-21. Account: management account (ID redacted).

A long-lived IAM user with an access key is the classic source of leaked AWS credentials.
To prove the retirement process, a stand-in legacy user was created on purpose
(`legacy-reporting-svc`, no console access, ReadOnlyAccess, one access key that was never
used and whose secret was never displayed or stored), then retired.

## 1. Find it (credential report, 18:26:59 AEDT)


Reading the report:

- `legacy-reporting-svc`: `password_enabled=false`, `access_key_1_active=true`,
  `access_key_1_last_used_date=N/A` → a long-lived key that has never been used. Retire it.
- `<root_account>`: `mfa_active=true`, `access_key_1_active=false`, `access_key_2_active=false`
  → root has MFA and no access keys (also evidence for T6.1).

## 2. Deactivate the key (reversible)

Access key status set to **Inactive** (`screenshots/T6.6-2-key-deactivated.png`). In production,
wait (for example 7 days) and watch for failures before deleting, so a hidden dependency shows
up while the change can still be undone.

## 3. Delete the key, then the user

"Access key deleted", then "User 'legacy-reporting-svc' deleted".

## 4. Verify

IAM users: **0** (`screenshots/T6.6-4-iam-users-zero.png`). All human access now goes through
IAM Identity Center with short-lived credentials.
